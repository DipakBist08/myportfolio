Playwright API testing in Python means sending HTTP requests through Playwright's `APIRequestContext` and checking the responses with pytest, without opening a browser. You get Playwright's fixtures, assertions and auth handling for your API layer, in the same project as your UI tests. This guide builds a complete test suite step by step, and every test in it was run and passes.

<KeyTakeaways>
- `APIRequestContext` sends HTTP requests directly. The suite in this guide passes with no browsers installed.
- Create the request context once per test session, with the base URL and the auth header.
- For every write, check the status, the body and the stored data. A `201` alone proves little.
- `jsonschema` ignores `"format"` rules such as email unless you pass a `FormatChecker`.
- Test `401`, `403` and bad input as carefully as the happy path.
</KeyTakeaways>

## What do you need for Playwright API testing in Python?

You need Python 3.10 or newer and two packages: `pytest-playwright`, which installs Playwright and pytest, and `jsonschema` for response validation. You do not need to run `playwright install`, because API tests never start a browser.

```bash
python -m venv .venv
source .venv/bin/activate   # on Windows: .venv\Scripts\activate
pip install pytest-playwright jsonschema
```

These are the exact versions this guide was tested with:

```text title="requirements.txt"
playwright==1.65.1
pytest==9.2.0
pytest-playwright==0.10.0
jsonschema==4.26.0
```

<Callout type="info" title="No browser download needed">
  `pip install playwright` installs the library and its driver, not the browsers. Browsers come from the separate `playwright install` step, which API-only suites can skip. The example suite for this guide passes with Playwright pointed at an empty browser folder (`PLAYWRIGHT_BROWSERS_PATH`), so no browser is involved at any point.
</Callout>

## What API will the tests run against?

The examples test a small users API. So that every example runs for anyone, with no account and no network access, the example project includes a mock of that API: `mock_api.py`, written with the Python standard library only. It starts on a free local port when the test session starts. To point the same tests at another API, set `API_BASE_URL`.

| Request | Success | Expected errors |
|---|---|---|
| `GET /users/{id}` | `200` with the user | `401`, `404` |
| `POST /users` | `201` with the new user | `400` missing field, `422` invalid value, `409` email taken, `401`, `403` |
| `PATCH /users/{id}` | `200` with the updated user | `422` invalid value, `404`, `401`, `403` |
| `DELETE /users/{id}` | `204` with no body | `404`, `401`, `403` |
| `GET /admin/settings` | `200` | `401`, `403` |

There are two tokens: `admin-token` can read and write, and `viewer-token` can only read. The complete project, with the mock and all 25 tests, is in the [Playwright API testing example project on GitHub](https://github.com/DipakBist08/myportfolio/tree/main/blog/examples/playwright-api-testing-guide).

## How do you set up an APIRequestContext with pytest?

Create one `APIRequestContext` per test session in `conftest.py`, with the base URL and the headers every request needs. pytest-playwright provides the `playwright` fixture you build it from. Dispose of the context at the end of the session to free its memory.

```python title="conftest.py"
import os
import uuid
from typing import Iterator

import pytest
from playwright.sync_api import APIRequestContext, Playwright

import mock_api


@pytest.fixture(scope="session")
def base_url() -> Iterator[str]:
    """Use API_BASE_URL when it is set; otherwise start the local mock API."""
    external = os.environ.get("API_BASE_URL")
    if external:  # an empty value (an unset CI variable) falls through to the mock
        yield external
        return
    server, url = mock_api.start()
    yield url
    server.shutdown()


def new_context(playwright: Playwright, base_url: str, token: str | None) -> APIRequestContext:
    headers = {"Accept": "application/json"}
    if token:
        headers["Authorization"] = f"Bearer {token}"
    return playwright.request.new_context(base_url=base_url, extra_http_headers=headers)


def token(name: str, mock_default: str) -> str:
    # `or`, not a get() default: CI sets the variable to "" when a secret is missing.
    return os.environ.get(name) or mock_default


@pytest.fixture(scope="session")
def api_context(playwright: Playwright, base_url: str) -> Iterator[APIRequestContext]:
    """Requests sent as an admin. The token comes from the environment, never from the code."""
    context = new_context(playwright, base_url, token("API_TOKEN", "admin-token"))
    yield context
    context.dispose()


@pytest.fixture(scope="session")
def viewer_context(playwright: Playwright, base_url: str) -> Iterator[APIRequestContext]:
    """Requests sent as a read-only user."""
    context = new_context(playwright, base_url, token("API_VIEWER_TOKEN", "viewer-token"))
    yield context
    context.dispose()


@pytest.fixture(scope="session")
def anonymous_context(playwright: Playwright, base_url: str) -> Iterator[APIRequestContext]:
    """Requests sent with no token at all."""
    context = new_context(playwright, base_url, token=None)
    yield context
    context.dispose()


@pytest.fixture
def unique_email() -> str:
    """A fresh address per test, so tests never collide on the unique-email rule."""
    return f"qa-{uuid.uuid4().hex[:12]}@example.com"


@pytest.fixture
def created_user(api_context: APIRequestContext, unique_email: str) -> Iterator[dict]:
    """Create a user for one test and delete it afterwards, even if the test fails."""
    response = api_context.post("/users", data={"name": "QA Tester", "email": unique_email, "role": "viewer"})
    assert response.status == 201, response.text()
    user = response.json()
    yield user
    api_context.delete(f"/users/{user['id']}")  # 404 is fine if the test already deleted it
```

Three details in this file prevent common problems:

- **The token comes from the environment.** `API_TOKEN` is read with `or` instead of a `get()` default, because CI systems pass a missing secret as an empty string.
- **Every test gets its own email address.** `unique_email` stops tests from colliding on the "email must be unique" rule, so they can run in any order, or twice in a row.
- **Test data is cleaned up.** `created_user` deletes the user after the test, even when the test fails, because pytest runs fixture teardown either way.

Official references: [API testing in the Playwright for Python docs](https://playwright.dev/python/docs/api-testing) and [how pytest fixtures work](https://docs.pytest.org/en/stable/how-to/fixtures.html).

## How do you test a GET request?

Send the request, check the status, then check the body. `expect(response).to_be_ok()` passes for any status from 200 to 299, so compare `response.status` directly when the exact code matters, as in the 404 test below.

```python title="tests/test_users_read.py"
from playwright.sync_api import APIRequestContext, expect


def test_get_user_returns_the_user(api_context: APIRequestContext):
    response = api_context.get("/users/1")

    expect(response).to_be_ok()  # any 2xx status

    body = response.json()
    assert body["id"] == 1
    assert body["email"] == "asha@example.com"
    assert response.headers["content-type"] == "application/json"


def test_get_missing_user_returns_404(api_context: APIRequestContext):
    response = api_context.get("/users/999999")

    assert response.status == 404
    assert response.json() == {"error": "not_found"}


def test_list_users_includes_a_created_user(api_context: APIRequestContext, created_user: dict):
    response = api_context.get("/users")

    expect(response).to_be_ok()
    assert created_user["id"] in [user["id"] for user in response.json()]
```

## How do you test POST, PATCH and DELETE requests?

For every write, check three things: the status code, the response body, and the stored data, by reading the record back. An API can answer `201` or `200` and still fail to save the change, and only the read-back catches that.

Written as a manual test case, the flow looks like this. The tests below automate each step.

<TestCase
  id="API-001"
  title="Create, update and delete a user through the REST API"
  objective="The users API stores changes and removes deleted users"
  preconditions="An admin token. The email address used is not taken."
  testData={`name: QA Tester\nemail: a new, unique address\nrole: viewer`}
  type="API"
  priority="high"
  author="Dipak Bist"
  steps={[
    { action: "POST /users with the test data", expected: "201, and the body echoes the name, email and role with a numeric id" },
    { action: "PATCH /users/{id} with a new email", expected: "200, and GET /users/{id} returns the new email" },
    { action: "DELETE /users/{id}", expected: "204 with no body" },
    { action: "GET /users/{id}", expected: "404: the user is gone" },
  ]}
/>

```python title="tests/test_users_write.py"
from playwright.sync_api import APIRequestContext, expect


def test_create_user(api_context: APIRequestContext, unique_email: str):
    payload = {"name": "QA Tester", "email": unique_email, "role": "viewer"}

    response = api_context.post("/users", data=payload)  # a dict is sent as JSON

    assert response.status == 201
    body = response.json()
    assert isinstance(body["id"], int)
    assert {key: body[key] for key in payload} == payload

    api_context.delete(f"/users/{body['id']}")  # clean up what this test created


def test_update_user_email(api_context: APIRequestContext, created_user: dict, unique_email: str):
    new_email = f"updated-{unique_email}"

    response = api_context.patch(f"/users/{created_user['id']}", data={"email": new_email})

    expect(response).to_be_ok()
    assert response.json()["email"] == new_email
    # Read it back: the update must be stored, not only echoed in the response.
    assert api_context.get(f"/users/{created_user['id']}").json()["email"] == new_email


def test_delete_user(api_context: APIRequestContext, created_user: dict):
    user_url = f"/users/{created_user['id']}"

    delete_response = api_context.delete(user_url)
    assert delete_response.status == 204

    assert api_context.get(user_url).status == 404  # it is really gone
    assert api_context.delete(user_url).status == 404  # deleting twice is not a success
```

Two details worth copying:

- **`data=` with a dict is sent as JSON.** Playwright also sets `Content-Type: application/json` for you. Use `form=` for form-encoded bodies and `multipart=` for file uploads. See the [APIRequestContext reference](https://playwright.dev/python/docs/api/class-apirequestcontext).
- **The delete test deletes twice.** In this API's contract the second call returns `404`. Some APIs return `204` again by design. Whichever your API documents, test it, so a change in behavior gets noticed.

## How do you validate an API response with JSON Schema?

Describe the expected shape of a response once, as a JSON Schema, and validate responses against it. Schema checks catch a renamed field, a wrong type or an unexpected extra field, which checks on one or two values miss.

```python title="tests/test_schema.py"
import pytest
from jsonschema import Draft202012Validator, FormatChecker, ValidationError
from playwright.sync_api import APIRequestContext

USER_SCHEMA = {
    "type": "object",
    "required": ["id", "name", "email", "role"],
    "properties": {
        "id": {"type": "integer"},
        "name": {"type": "string", "minLength": 1},
        "email": {"type": "string", "format": "email"},
        "role": {"type": "string", "enum": ["admin", "editor", "viewer"]},
    },
    # Fail when the API starts returning a field nobody agreed on.
    "additionalProperties": False,
}

# "format" is only checked when a FormatChecker is passed in.
validator = Draft202012Validator(USER_SCHEMA, format_checker=FormatChecker())


def test_user_response_matches_schema(api_context: APIRequestContext):
    body = api_context.get("/users/1").json()

    validator.validate(body)  # raises ValidationError on a mismatch


def test_every_listed_user_matches_schema(api_context: APIRequestContext):
    for user in api_context.get("/users").json():
        validator.validate(user)


@pytest.mark.parametrize(
    "broken_user",
    [
        {"id": "1", "name": "Asha Rai", "email": "asha@example.com", "role": "admin"},  # id is a string
        {"id": 1, "name": "Asha Rai", "email": "not-an-email", "role": "admin"},  # bad email format
        {"id": 1, "name": "Asha Rai", "email": "asha@example.com", "role": "owner"},  # unknown role
        {"id": 1, "name": "Asha Rai", "email": "asha@example.com"},  # role is missing
        {"id": 1, "name": "Asha Rai", "email": "asha@example.com", "role": "admin", "password": "x"},  # extra field
    ],
)
def test_schema_rejects_a_broken_user(broken_user: dict):
    """Prove the schema can fail. A schema that accepts everything protects nothing."""
    with pytest.raises(ValidationError):
        validator.validate(broken_user)
```

`"additionalProperties": False` matters most for fields that should never leave the server, such as a password hash: the extra-field case in the last test is exactly that bug.

<Callout type="warning" title="Formats are not checked unless you ask">
  In the `jsonschema` library, `"format": "email"` is only an annotation by default, so `not-an-email` passes. Pass `format_checker=FormatChecker()` to enforce formats, as above. See [validating formats in the jsonschema docs](https://python-jsonschema.readthedocs.io/en/stable/validate/).
</Callout>

## How do you test 401 and 403 responses?

Test both failure modes. `401 Unauthorized` means the request has no valid credentials, and `403 Forbidden` means the credentials are valid but not allowed to do this (MDN: [401 Unauthorized](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/401), [403 Forbidden](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/403)). Give each role its own request context, so every test shows who is calling.

```python title="tests/test_auth.py"
from playwright.sync_api import APIRequestContext, Playwright


def test_401_without_a_token(anonymous_context: APIRequestContext):
    response = anonymous_context.get("/users/1")

    assert response.status == 401
    assert response.json() == {"error": "unauthorized"}


def test_401_with_an_invalid_token(playwright: Playwright, base_url: str):
    context = playwright.request.new_context(
        base_url=base_url,
        extra_http_headers={"Authorization": "Bearer not-a-real-token"},
    )
    try:
        assert context.get("/users/1").status == 401
    finally:
        context.dispose()


def test_viewer_can_read(viewer_context: APIRequestContext):
    assert viewer_context.get("/users/1").status == 200


def test_403_when_a_viewer_opens_an_admin_endpoint(viewer_context: APIRequestContext):
    response = viewer_context.get("/admin/settings")

    assert response.status == 403
    assert response.json() == {"error": "forbidden"}


def test_403_when_a_viewer_tries_to_write(viewer_context: APIRequestContext, api_context: APIRequestContext, unique_email: str):
    response = viewer_context.post("/users", data={"name": "Should Not Exist", "email": unique_email})

    assert response.status == 403
    # The status code alone is not enough: check that nothing was created.
    assert unique_email not in [user["email"] for user in api_context.get("/users").json()]
```

The last test is the one many suites skip: it checks that the viewer's rejected request created nothing. A `403` with a side effect is still a security bug.

## How do you write negative API tests?

List the invalid inputs in a parametrize table, one row per case, with the expected status and the field the error should name. For each row, check three things: the status, the error body, and that nothing was created.

```python title="tests/test_negative.py"
import pytest
from playwright.sync_api import APIRequestContext


@pytest.mark.parametrize(
    "payload, expected_status, expected_fields",
    [
        pytest.param({}, 400, ["name", "email"], id="empty body"),
        pytest.param({"name": "No Email"}, 400, ["email"], id="email missing"),
        pytest.param({"name": "", "email": "a@example.com"}, 422, ["name"], id="name empty"),
        pytest.param({"name": "x" * 101, "email": "a@example.com"}, 422, ["name"], id="name too long"),
        pytest.param({"name": "Bad Email", "email": "not-an-email"}, 422, ["email"], id="email invalid"),
        pytest.param({"name": "Bad Role", "email": "a@example.com", "role": "owner"}, 422, ["role"], id="role unknown"),
    ],
)
def test_create_user_rejects_bad_input(api_context: APIRequestContext, payload, expected_status, expected_fields):
    users_before = len(api_context.get("/users").json())

    response = api_context.post("/users", data=payload)

    assert response.status == expected_status
    assert response.json()["fields"] == expected_fields  # the error says which fields are wrong
    assert len(api_context.get("/users").json()) == users_before  # and nothing was created


def test_create_user_rejects_a_duplicate_email(api_context: APIRequestContext, created_user: dict):
    response = api_context.post("/users", data={"name": "Twin", "email": created_user["email"]})

    assert response.status == 409
    assert response.json() == {"error": "email_taken"}
```

The split between `400` and `422` is this API's contract. Your API may use `400` for every validation error: test what your API documents, not these numbers. The `id=` labels make each case readable in the test report; see [parametrizing tests](https://docs.pytest.org/en/stable/how-to/parametrize.html) in the pytest docs.

## How do you run Playwright API tests in CI?

Install the requirements and run pytest. There is no `playwright install` step, because API tests need no browser. Store the token as a repository secret and pass it to the test step as an environment variable.

```yaml title=".github/workflows/api-tests.yml"
name: API tests

on: [push, pull_request]

jobs:
  api-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: "3.12"
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Run API tests
        run: pytest -v
        env:
          API_BASE_URL: ${{ vars.API_BASE_URL }}
          API_TOKEN: ${{ secrets.API_TOKEN }}
```

When `API_BASE_URL` is not set, the tests start the mock API, so the workflow also runs in a fork that has no secrets.

## What are the most common mistakes in Playwright API tests?

- **A token hardcoded in `conftest.py`.** It ends up in Git history. Read it from an environment variable.
- **Checking only the status code.** Check the body too and, for writes, read the data back.
- **Fixed test data.** A test that always creates `qa@example.com` collides with itself on the second run. Generate unique values.
- **No cleanup.** Shared test environments fill up with leftover records. Delete what each test creates, in a fixture.
- **Returning a value from a test so a later test can use it.** pytest 9 warns with `PytestReturnNotNoneWarning`, and no other test can read the value. Share data through fixtures instead.
- **Trusting `"format"` in a schema without a `FormatChecker`.** The check silently does nothing.
